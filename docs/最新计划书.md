## 一、系统架构与通信拓扑

```
                    远程机库调度地面站
                   (MQTT Broker / 调度平台)
                          |
                    MQTT (4G/WAN)
                          |
    ┌─────────────────────┴─────────────────────┐
    │              RK3568 智能主控                │
    │                                             │
    │  [MQTT客户端]  [MAVLink解析]  [决策引擎]     │
    │  [串口通信]    [摄像头拉流]   [升级管理]     │
    │                                             │
    │   以太网口 ─── 网络摄像头 (RTSP直连)          │
    │   4G路由器 ─── 无人机机载4G图数一体模块(TCP)   │
    │   USB口    ─── STM32H743 (CDC虚拟串口)       │
    └─────────────────────────────────────────────┘
```

### 通信链路一览

| 链路 | 方式 | 协议 | 方向 | 带宽 |
|------|------|------|------|------|
| RK3568 ↔ 地面站 | 4G/WAN | MQTT (JSON) | 双向 | ~10-50 KB/s |
| RK3568 ↔ 无人机 | 机载4G图数一体模块(TCP) | MAVLink v2 | 下行遥测为主 | ~3-20 KB/s |
| RK3568 ↔ STM32 | USB CDC 虚拟串口 | 自定义二进制协议 | 双向 | ~1-10 KB/s |
| RK3568 ↔ 摄像头 | 以太网直连 | RTSP | 上行视频 | ~1-4 MB/s |


## 二、开发原则与高效策略

### 核心原则（牢记）

| # | 原则 | 说明 |
|---|------|------|
| 1 | **只用 Python** | 不写C++，不碰交叉编译。Python -> SCP -> 运行，三秒部署 |
| 2 | **开源优先** | MQTT=paho-mqtt, MAVLink=pymavlink, 串口=pyserial, 视频=FFmpeg/GStreamer |
| 3 | **先跑通再完善** | 第一阶段目标：MQTT能收发 + 串口能通信，其他后续加 |
| 4 | **不用 ROS** | 你的场景是智能网关不是自主机器人，ROS 过度设计 |
| 5 | **STM32 独立** | STM32工程不在此项目内，只管通信协议对接 |
| 6 | **配置文件驱动** | 所有参数放 config.yaml，不改代码 |

### 高效开发流程

```
PC(VS Code) --写代码--> git push
    |
    +--SCP上传--> RK3568 --python3 main.py--> 运行
    |
    +--SSH--> tail -f logs/app.log --> 实时看日志
```

**推荐工具链：VS Code + Remote-SSH 插件**（在PC上直接编辑RK3568上的文件，体验如同本地开发）

## 五、STM32 通信协议规范

> 📌 本节供 STM32 固件团队参考。STM32 工程独立维护，只需按此协议实现 USB CDC 通信即可。

### 5.1 物理层

| 参数 | 值 |
|------|-----|
| 接口 | USB CDC ACM |
| 波特率 | 115200 |
| 数据位/停止位/校验 | 8 / 1 / 无 |

### 5.2 帧结构

```
+--------+--------+--------+----------+----------+--------+--------+
| 帧头   | 地址   | 命令   | 数据长度  | 数据      | CRC16  | 帧尾   |
| 2B     | 1B     | 1B     | 2B(LE)   | NB       | 2B     | 2B     |
| 0xAA55 | 0x01   | CMD    | Len      | Payload  | MODBUS | 0x55AA |
+--------+--------+--------+----------+----------+--------+--------+
```

最小帧9字节(N=0)，最大帧521字节(N<=512)。
CRC16 计算范围：地址 + 命令 + 长度(2B) + 数据(NB)。

### 5.3 下行指令（RK3568 -> STM32）

| 命令码 | 指令 | 数据 | 说明 |
|--------|------|------|------|
| 0x01 | OPEN_DOOR | 无 | 开舱门 |
| 0x02 | CLOSE_DOOR | 无 | 关舱门 |
| 0x03 | LOCK | 无 | 上锁 |
| 0x04 | UNLOCK | 无 | 解锁 |
| 0x10 | GET_STATUS | 无 | 查询状态 |
| 0x11 | GET_SENSORS | 无 | 查询传感器 |
| 0x20 | SOFT_RESET | 无 | 软复位 |
| 0x30 | ENTER_IAP | 无 | 进入升级模式 |
| 0x31 | IAP_DATA | 4B块号+数据 | 固件数据块 |
| 0x32 | IAP_FINISH | 4B校验 | 升级完成 |

### 5.4 上行数据（STM32 -> RK3568）

| 命令码 | 上报 | 触发 | 数据区 |
|--------|------|------|--------|
| 0x80 | STATUS_REPORT | 周期500ms | 8B: 门(1B)+锁(1B)+告警(2B)+温度(2B)+湿度(2B) |
| 0x81 | SENSOR_DATA | 周期1s | 8B: 电压(2B)+电流(2B)+预留(4B) |
| 0x82 | ALARM | 事件即时 | 4B位掩码 |
| 0x83 | CMD_ACK | 收指令后 | 3B: 原指令(1B)+结果(1B)+错误码(1B) |

**STATUS_REPORT 字段说明：**
- 舱门: 0x00=关闭, 0x01=打开, 0x02=运动中, 0xFF=未知
- 锁:   0x00=解锁, 0x01=上锁, 0xFF=未知
- 温度: int16, 0.1°C单位 (285=28.5°C)
- 湿度: uint16, 0.1%单位 (650=65.0%)

**CMD_ACK 结果码:** 0x00=成功, 0x01=失败, 0x02=超时, 0xFF=未知指令

### 5.5 CRC16 参考实现（C语言，STM32侧可直接用）

```c
// MODBUS-CRC16, 多项式 0x8005
uint16_t crc16_modbus(const uint8_t *data, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
            else             crc = (crc >> 1);
        }
    }
    return crc;
}
```

### 5.6 通信时序

```
RK3568                           STM32
  |-- 指令帧(含CRC) ------------>|
  |                              |-- 解析+执行
  |<-- CMD_ACK(含CRC) ----------|
  |                              |
  |<-- STATUS_REPORT(500ms) ----|  周期上报
  |<-- SENSOR_DATA(1s) ---------|  周期上报
  |<-- ALARM(事件) -------------|  即时上报

超时: 500ms | 重试: 3次 | 3次均失败 -> 标记STM32通信异常
```


## 六、RK3568 开发上手指南（零基础）

### 6.1 你需要知道的几个概念

| 概念 | 大白话 |
|------|--------|
| **RK3568** | 一块 ARM 架构的小电脑，跑 Linux 系统 |
| **SSH** | 从你的PC远程登录到RK3568的命令行 |
| **SCP** | 从你的PC传文件到RK3568 |
| **aarch64** | ARM 64位架构，RK3568的CPU架构 |
| **交叉编译** | 在x86 PC上编译出ARM上能跑的程序 → **我们不用这个，直接用Python** |

### 6.2 第一步：确认 RK3568 环境（SSH进去执行）

```bash
# 用 MobaXterm SSH 连接到 RK3568，依次执行：

# 1. 看系统版本
uname -a
cat /etc/os-release

# 2. 看Python版本
python3 --version

# 3. 看有没有pip3
pip3 --version

# 4. 看磁盘空间
df -h

# 5. 看内存
free -h

# 6. 看有没有 /dev/ttyACM0 (接上STM32后执行)
ls /dev/ttyACM*
ls /dev/ttyUSB*

# 7. 看网络IP
ip addr show
```

> 📌 把以上命令的输出记下来，这是你的环境基线。

### 6.3 第二步：安装 Python 依赖

```bash
# SSH 到 RK3568 上执行：

# 如果没有pip3，先安装
sudo apt update
sudo apt install python3-pip -y

# 安装项目需要的库
pip3 install pyserial paho-mqtt pymavlink pyyaml

# 摄像头相关（按需）
sudo apt install ffmpeg -y

# 验证安装
python3 -c "import serial; import paho.mqtt.client; import pymavlink; print('OK')"
```

### 6.4 第三步：PC 开发 → RK3568 运行（核心流程）

**方式A：SCP 手动部署（最简单，推荐起步用）**

```bash
# === 在PC的 PowerShell/CMD 中执行 === #

# 1. 把代码上传到RK3568
scp -r rk3568_app root@192.168.x.x:/home/root/app

# 2. SSH进去运行
ssh root@192.168.x.x
cd /home/root/app
python3 main.py

# 3. 后台运行（关SSH后不中断）
nohup python3 main.py > /dev/null 2>&1 &

# 4. 看日志
tail -f data/logs/app.log
```

**方式B：VS Code Remote-SSH（推荐长期使用）**

```
1. 在PC上安装 VS Code + Remote-SSH 插件
2. Ctrl+Shift+P -> Remote-SSH: Connect to Host
3. 输入: root@192.168.x.x
4. 连接成功后，在VS Code里直接打开 /home/root/app 目录
5. 编辑文件 = 直接在RK3568上编辑！Ctrl+S = 保存到RK3568！
6. VS Code 内置终端就是SSH终端，直接 python3 main.py
```

> 📌 **强烈推荐方式B**，开发体验和本地几乎一样。

### 6.5 第四步：设置开机自启动

```bash
# SSH 到 RK3568 上执行：

# 1. 创建 systemd 服务文件
sudo nano /etc/systemd/system/hangar.service
```

```ini
# 填入以下内容：
[Unit]
Description=Hangar Control System
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/home/root/app
ExecStart=/usr/bin/python3 /home/root/app/main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 2. 启用并启动
sudo systemctl daemon-reload
sudo systemctl enable hangar
sudo systemctl start hangar

# 3. 查看状态
sudo systemctl status hangar
journalctl -u hangar -f    # 实时看日志

# 4. 常用命令
sudo systemctl stop hangar     # 停止
sudo systemctl restart hangar  # 重启
sudo systemctl disable hangar  # 取消自启动
```

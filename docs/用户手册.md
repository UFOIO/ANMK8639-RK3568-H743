#### 13.9.1 健康检查 (4G WiFi 后台线程)

core/app_state.py 启动时起一个后台线程, 每 10 秒检查一次 4G WiFi 状态:

`python
# core/app_state.py
def _check_gimbal_wifi_once():
    # 用 nmcli 查 active connection
    rc = subprocess.run(["nmcli", "-t", "-f", "NAME,STATE", "connection", "show", "--active"],
                        capture_output=True, text=True, timeout=3)
    for line in rc.stdout.splitlines():
        if line.startswith("H4T_4G:activated"):
            ssid = subprocess.run(["iwgetid", "-r"], capture_output=True, text=True).stdout.strip()
            return True, ssid or "H4T_4G"
    # Fallback: 看 wlan0 有没有 IP
    ...
`

结果写到 system.gimbal_wifi_connected / system.gimbal_wifi_ssid, dashboard 自动取用。

**效果**: 顶部 4G WiFi 指示器 + "云台存储"卡片 **完全同步**, 真实反映 WiFi 实际状态。

  var valEl = item.querySelector(".gauge-value");

## 一、系统概述

ANMK8639 机库智能控制系统运行于 RK3568 边缘计算平台，核心职责：

| 功能 | 说明 |
|------|------|
| MAVLink 遥测 | 通过 TCP(4G图传) 或 USB串口 接收飞控心跳/姿态/GPS/电池 |
| MQTT 通信 | 对接远程地面站，上报机库状态、转发控制指令 |
| STM32 控制 | USB CDC 串口控制下位机（开门/关门/锁止/解锁/温湿度） |
| RTSP 截图 | 定时抓取摄像头画面，存档备查 |
| 决策引擎 | 自动规则：RTL开舱、低电量告警、失联告警 |
| Web 看板 | 浏览器实时监控 + 配置管理 + 手动控制 |

**硬件架构**：

```
飞控(Pixhawk) ──USB──┐
                      ├── RK3568 ── 4G/WiFi ── 地面站
STM32H743 ──USB──────┘        │
                               └── 摄像头(RTSP)
```

#### 13.9.7 WiFi 状态误报 bug 修复 (v1.2.2)

**问题**: 已断开 4G WiFi, 但 dashboard 顶部 "4G WiFi" 指示器 + "云台存储" 卡片还显示"已连接"。

**根因** (modules/dashboard.html 旧版本): 两个地方用了**错误**的 OR 逻辑:

`js
// 旧代码 (BUG)
var wifi = d.gimbal_wifi || {};
var sysNet = (d.system && d.system.network) || d.network || "";
var isOn = (wifi.connected === true) || sysNet === "connected" || sysNet === "online";
//                                              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                              这是公网连通性, 不是 4G WiFi 状态!
`

d.system.network 由 _get_system_info() 通过 socket 连 8.8.8.8:53 测得, 表示**公网通不通**。
只要 eth0 默认路由还在 (公网通), system.network === "connected", 4G WiFi 断开也会被误判为"已连接"。

**修复**: dashboard **只**看 d.gimbal_wifi.connected (由 core/app_state.py 后台线程每 10s 调 
mcli 查 H4T_4G 状态写入):

`js
// 新代码 (FIXED)
function getGimbalWifiConnected(d) {
  if (d.gimbal_wifi && typeof d.gimbal_wifi.connected === "boolean") {
    return d.gimbal_wifi.connected;
  }
  if (d.gimbal_wifi && d.gimbal_wifi.ssid) return true;
  return false;
}

function getGimbalWifiSsid(d) {
  if (d.gimbal_wifi && d.gimbal_wifi.ssid) return d.gimbal_wifi.ssid;
  return "";
}
`

updateWiFiStatus() 和 updateConnectionCards() 都改用 getGimbalWifiConnected(d), 不再读 system.network。

### 3.5 数据流解读

| 前缀 | 含义 | 刷新频率 |
|------|------|----------|
| `SYS:` | 系统负载/内存/运行时间 | 1Hz |
| `DATA:` | 四模块连接状态：MAVLink/MQTT/STM32/Camera | 1Hz |
| `TELEM:` | 无人机遥测：飞行模式/高度/速度/电量/卫星 | 1Hz |
| `MAVLink HB:` | 飞控心跳原始数据 | 按飞控发送频率 |

**连接状态标识**：
- `UP` / `DOWN` — 模块连接状态
- `HB:0s` — 距上次心跳秒数（`--` 表示从未收到）
- `MSG:--` — 距上次消息秒数
- `RPT:--` — 距上次上报秒数
- `SNAP:--` — 距上次截图秒数

总览页面数据每 250ms 自动刷新（4Hz），与飞控遥测刷新率匹配。

系统资源栏底部显示 **Broker 状态**（✅ 运行 / ❌ 停止）。

后台提供 SSE 实时推送端点 `/api/stream`（100ms 间隔），供高级用户自行对接。

### 4.4 MAVLink 连接方式

在「系统配置 → MAVLink 无人机」中切换：

| 连接方式 | 使用场景 | 需填参数 |
|----------|----------|----------|
| TCP (4G图传) | 远程飞控通过 4G 模块连接 | 4G模块IP + 端口(默认5760) |
| 串口 (USB直连) | USB 线直接插飞控 | 串口设备路径 + 波特率(默认115200) |

### 4.5 STM32 串口选择

独立串口下拉框，避免与 MAVLink 抢口：


## 五、配置文件详解

配置文件位置：

### 5.1 日志

```yaml
log:
  level: INFO           # DEBUG | INFO | WARNING | ERROR
  format: "text"        # text(人读) | json(机器读)
  dir: ./data/logs
  max_days: 30          # 日志保留天数
```

### 5.2 MQTT 地面站

```yaml
mqtt:
  enabled: false                # 是否启用 MQTT
  broker: "mqtt.example.com"    # Broker 地址
  port: 1883                    # 端口
  username: "admin"             # 用户名
  password: "your_password"     # 密码
  keepalive: 30                 # 心跳间隔(秒)
  status_interval: 5            # 状态上报间隔(秒)
  topic_prefix: "hangar/"       # 主题前缀
  qos: 1                        # QoS 等级(0|1|2)
  reconnect_min: 2              # 重连最小间隔(秒)
  reconnect_max: 60             # 重连最大间隔(秒)
```

### 5.3 MAVLink 无人机

```yaml
mavlink:
  connection: "tcp"             # 连接方式：tcp(4G图传) | serial(USB直连)
  host: "192.168.x.x"           # TCP 模式：4G模块IP
  port: 5760                    # TCP 模式：端口
  device: "/dev/ttyACM0"        # 串口模式：设备路径
  baudrate: 115200              # 串口模式：波特率
  heartbeat_timeout: 5          # 心跳超时(秒)，超时触发失联告警
  system_id: 255                # MAVLink 系统ID
  reconnect_interval: 3         # 重连间隔(秒)
```

### 5.4 STM32 串口

```yaml
stm32:
  port: "/dev/ttyUSB0"          # 串口设备路径
  baudrate: 115200              # 波特率
  data_bits: 8                  # 数据位
  parity: "N"                   # 校验位：N(无)|E(偶)|O(奇)
```

## 七、常见问题

### Q1: MAVLink 显示 DOWN 无心跳

1. 检查连接方式：TCP 模式确认 4G 模块 IP 可达 `ping <IP>`
2. 串口模式确认设备存在 `ls /dev/ttyACM* /dev/ttyUSB*`
3. 检查 MAVLink 和 STM32 是否用了同一串口（不能共用）
4. 尝试 `hangar restart`

### Q2: STM32 反复 DISCONNECTED

1. 确认 STM32 板已上电，USB 线已插
2. 确认配置的串口设备存在 `ls -la <设备路径>`
3. 确认串口没有被 MAVLink 占用

### Q3: 网页显示问号

1. 确认 `dashboard.html` 是最新版
2. 清除浏览器缓存后刷新

### Q4: 配置保存后不生效

WebUI 保存时会自动重启服务（约 3-5 秒）。若仍不生效：
1. 确认保存时有绿色"已保存"提示
2. 手动执行 `sudo systemctl restart hangar`

### Q5: 代码更新后配置丢失

不会丢失。WebUI 修改的配置保存在 `/etc/hangar/local.yaml`，代码更新只覆盖默认模板。
`local.yaml` 永不覆盖，始终保留你的配置。

### Q6: 登录认证怎么开关

**开启**：WebUI → 系统配置 → 认证设置 → 勾选"启用登录认证" → 保存。

**密码输入框右侧有"显/隐"按钮，可查看实际输入的密码。**

> ⚠️ **应急手段**：如果忘记密码或登录失败无法进入 WebUI，SSH 执行以下命令强制关闭认证：
> ```bash
> sudo tee /etc/hangar/local.yaml << 'EOF'
> auth:
>   enabled: false
> EOF
> sudo rm -rf /opt/hangar/modules/__pycache__
> sudo systemctl restart hangar
> ```
> 关闭后可无密码进入 WebUI，重新设置密码后再开启。

默认用户名 `admin`，默认密码 `admin123`，建议首次登录后修改。

### Q7: 横滚/俯仰角度不对

已修复。飞控返回的是弧度值，系统自动转为角度（`math.degrees()`）。
横滚 ±180°，俯仰 ±90°，偏航角 -180°~+180° 为正确范围。

### Q8: CPU 显示跳动

已修复。CPU 每 2 秒采样一次（与 htop 一致），显示的是 EMA 平滑值，不会因刷新频率抖动。

### Q9: 数据延迟约 1 秒

已修复。总览页面每 250ms 轮询一次 /api/health（4Hz），与飞控遥测刷新率匹配。

### Q10: 如何查看实时飞控数据

```bash
hangar logs
# 或
hangar run
```
关注 `TELEM:` 行：飞行模式/高度/地速/电量/卫星数

### 10.1 双网卡架构

```
┌──────────────────────────────────────────────┐
│ RK3568                                        │
├──────────────────────────────────────────────┤
│ eth0 (192.168.2.78/24)  ← 主网/公网           │
│   └─ gateway 192.168.2.1                     │

│   └─ dnsmasq DHCP 给摄像头自动分 IP           │
│                                               │

│   └─ 自动连 H4T_4G                           │
│   └─ never-default                           │
│   └─ autoconnect-priority 100                │
│   └─ 飞机回来时自动重连 (wifi-watchdog)       │

│   └─ 广播 192.168.144.0/24 给客户            │
└──────────────────────────────────────────────┘
```

### 10.2 开机自启项

| 服务 | 作用 | 启动时机 |
|---|---|---|
| `systemd-networkd` | netplan 静态 IP | 开机 |
| `NetworkManager` | WiFi + autoconnect | 开机 |
| `wifi-autoconnect.service` | 开机 30s 后首次连 H4T_4G | 开机 |
| `wifi-watchdog.service` | 持续保活 (60s 检测) | 一直跑 |
| `iptables-persistent` | 恢复 FORWARD 规则 | 开机 |
| `go2rtc.service` | RTSP 代理 | 开机 |
| `hangar.service` | 主程序 | 开机 |
| `tailscaled.service` | Tailscale 守护 | 开机 |

### 10.3 重启验证 (8 步)

```bash
echo "=== 1. eth0 ==="; ip addr show eth0 | grep "inet "
echo "=== 2. WiFi ==="; nmcli device status | grep wlan0
echo "=== 3. soft-block ==="; rfkill list | grep -A 1 phy0
echo "=== 4. ip_forward ==="; cat /proc/sys/net/ipv4/ip_forward
echo "=== 5. iptables ==="; sudo iptables -L FORWARD -n | grep -E "192.168.144|policy"
echo "=== 6. Tailscale ==="; sudo tailscale status | head -3
echo "=== 7. 云台通 ==="; ping -c 2 192.168.144.25
echo "=== 8. 公网通 ==="; ping -c 2 baidu.com
```

**8 项全绿 = 网络地基正常**。

### 10.4 飞机离开/返回 WiFi 重连

- 飞机离库 → 4G 模块 WiFi 信号消失 → wlan0 自动断开
- 飞机返航进入机库范围 → 4G 模块 WiFi 信号再次出现
- **60 秒内**:
  - NetworkManager 扫描到 H4T_4G (优先级 100) → 自动重连
  - 或 wifi-watchdog 检测到断开 → 强制触发重连

### 10.5 一键重置网络 (万不得已)

```bash
sudo bash /home/kickpi/rk3568_app/deploy/setup_network.sh
sudo systemctl restart NetworkManager
sudo systemctl restart wifi-watchdog
```

## 十四、文件更新与上传流程 (新增 v1.1)

每次 PC 上的代码 (`.py` / `.html` / `.yaml` / `.sh`) 改动后,
需要按下面流程传到 RK3568。



> 💾 **改坏了怎么回滚?** 每次 patch 前会自动留一份 .bak 在同目录:
> - modules/dashboard.html.bak (v1.2 addGauge 闪烁 bug 修复前)
> - modules/dashboard.html.bak2 (v1.2.1 充电电量占位前)
>
> 回滚: sudo cp /opt/hangar/modules/dashboard.html.bak /opt/hangar/modules/dashboard.html && sudo systemctl restart hangar
### 14.1 文件映射表 (PC → 板子)

| PC 路径 | 板子路径 (开发副本) | 板子路径 (运行时) | 说明 |
|---|---|---|---|
| `rk3568_app/main.py` | `/home/kickpi/rk3568_app/main.py` | `/opt/hangar/main.py` | 入口 |
| `rk3568_app/config.yaml` | `/home/kickpi/rk3568_app/config.yaml` | `/etc/hangar/config.yaml` | **代码模板, 覆盖** |
| `rk3568_app/modules/*.py` | `/home/kickpi/rk3568_app/modules/` | `/opt/hangar/modules/` | 模块代码 |
| `rk3568_app/modules/*.html` | `/home/kickpi/rk3568_app/modules/` | `/opt/hangar/modules/` | 模板 |
| `rk3568_app/protocol/*.py` | `/home/kickpi/rk3568_app/protocol/` | `/opt/hangar/protocol/` | 协议 |
| `rk3568_app/utils/*.py` | `/home/kickpi/rk3568_app/utils/` | `/opt/hangar/utils/` | 工具 |
| `rk3568_app/deploy/*.sh` | `/home/kickpi/rk3568_app/deploy/` | `/opt/hangar/deploy/` | 部署脚本 |
| `rk3568_app/deploy/*.service` | - | `/etc/systemd/system/` | systemd 服务 |

> ⚠ `/etc/hangar/local.yaml` **永不覆盖** (用户配置: WiFi密码/Tailscale key等)

### 14.1.1 config.yaml vs local.yaml (重要!)

板子上有**两个**配置文件, 性质完全不同:

| 文件 | 性质 | 谁改 | 部署时怎么处理 |
|---|---|---|---|
| `/etc/hangar/config.yaml` | **代码模板/默认值** | 开发者 (你) | PC 代码更新 → 覆盖板子上同位置 |
| `/etc/hangar/local.yaml` | **用户配置/运行时值** | 用户在 dashboard 改 | **永不覆盖**, 保留用户的 WiFi 密码 / Tailscale key 等 |

**设计原理**: web_ui.py 加载顺序是 `config.yaml` → `local.yaml` (后者覆盖前者)。
所以 `config.yaml` 是"代码默认", `local.yaml` 是"用户覆盖", 互不冲突。

#### config.yaml 三种部署方式

##### 方式 A: 直接覆盖 (推荐, 改动小时)

```bash
ssh kickpi@192.168.2.78 "sudo cp /home/kickpi/rk3568_app/config.yaml /etc/hangar/config.yaml"
```

适用: 改动只是新增段 (如本次新增 `network:`), 旧字段不动。git diff 一眼看明白。

##### 方式 B: 先备份再覆盖 (更稳)

```bash
ssh kickpi@192.168.2.78 "sudo cp /etc/hangar/config.yaml /etc/hangar/config.yaml.bak.\$(date +%Y%m%d_%H%M%S) && sudo cp /home/kickpi/rk3568_app/config.yaml /etc/hangar/config.yaml && echo 'OK'"
```

出问题随时回滚: `sudo cp /etc/hangar/config.yaml.bak.* /etc/hangar/config.yaml`

##### 方式 C: Python 合并 (只注入新段, 保留板子上其他改动)

适用: 板子上 `config.yaml` 被你手动改过, 不想被覆盖丢失。

```bash
ssh kickpi@192.168.2.78 'sudo python3 << "PYEOF"
import yaml
with open("/home/kickpi/rk3568_app/config.yaml") as f:
    new = yaml.safe_load(f)
with open("/etc/hangar/config.yaml") as f:
    old = yaml.safe_load(f)
old["network"] = new.get("network", old.get("network", {}))
old.setdefault("vpn", {})["accept_dns"] = new.get("vpn", {}).get("accept_dns", False)
old.setdefault("gimbal_camera", {})["rtsp_url"] = new.get("gimbal_camera", {}).get("rtsp_url", "")
with open("/etc/hangar/config.yaml", "w") as f:
    yaml.safe_dump(old, f, allow_unicode=True, sort_keys=False)
print("merge OK")
PYEOF'
```

#### 怎么判断该用哪种?

```bash
# 先看 PC 和板子的差异 (在 PC 上跑):
ssh kickpi@192.168.2.78 "sudo diff /etc/hangar/config.yaml /home/kickpi/rk3568_app/config.yaml" | head -30
```

- 如果只有 `+` 没有 `-`: 用方式 A (只新增)
- 如果有 `-`: 用方式 B (先备份)
- 如果板子上有手动改过的痕迹: 用方式 C (合并)

### 14.5.1 PowerShell 常见坑

#### 坑 1: .ssh/config 权限报错

错误: `Bad permissions. Try removing permissions for user: ...\CodexSandboxUsers on file C:/Users/gjt/.ssh/config`

原因: Windows OpenSSH 安全检查失败, 沙箱用户不该有 .ssh/config 访问权限。

解决 (任选其一):
```powershell
# 方法 A: 移走 config (推荐, 一劳永逸)
Move-Item C:\Users\gjt\.ssh\config C:\Users\gjt\.ssh\config.broken

# 方法 B: 每条命令前加 -F /dev/null (绕过 config)
scp -F /dev/null <src> kickpi@<IP>:<dst>
ssh -F /dev/null kickpi@<IP> "<cmd>"
```

#### 坑 2: `$(date ...)` 被 PowerShell 解析

PowerShell 里 `$(...)` 是子表达式, 会报 `Get-Date` 错; `\$` 也转义不掉。

解决: 用**单引号**包整条 ssh 命令, PowerShell 不解析, Linux 端正常解析 `$(...)`:

```powershell
# 错的 (PowerShell 解析):
ssh kickpi@${IP} "sudo bash -c '... \$(date +%Y%m%d_%H%M%S) ...'"

# 对的 (单引号, 不解析):
ssh kickpi@${IP} 'sudo bash -c "... $(date +%Y%m%d_%H%M%S) ..."'
```

或者直接用固定备份名, 不用时间戳:
```bash
sudo cp /etc/hangar/config.yaml /etc/hangar/config.yaml.bak
```

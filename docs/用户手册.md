# ANMK8639 Hangar Control — 用户手册

> 版本：v1.0 | RK3568 + STM32H743 智能机库控制系统

---

## 一、系统概述

ANMK8639 机库智能控制系统运行于 RK3568 边缘计算平台，核心职责：

| 功能 | 说明 |
|------|------|
| MAVLink 遥测 | 通过 TCP(4G图传) 或 USB串口 接收飞控心跳/姿态/GPS/电池 |
| MQTT 通信 | 对接远程地面站，上报机库状态、转发控制指令 |
| STM32 控制 | USB CDC 串口控制下位机（开门/关门/锁止/解锁/温湿度） |
| RTSP 截图 | 定时抓取摄像头画面，存档备查 |
| 决策引擎 | 自动规则：RTL开舱、低电量告警、失联告警 |
| Web 看板 | 浏览器实时监控 + 配置管理 + 手动控制 |

**硬件架构**：

```
飞控(Pixhawk) ──USB──┐
                      ├── RK3568 ── 4G/WiFi ── 地面站
STM32H743 ──USB──────┘        │
                               └── 摄像头(RTSP)
```

## 三、CLI 命令参考

### 3.1 服务控制

```bash
hangar start          # 启动服务
hangar stop           # 停止服务
hangar restart        # 重启服务（所有模块重新初始化）
hangar reload         # 热重载配置（仅阈值/间隔生效，连接参数需 restart）
```

### 3.2 运行监控

```bash
hangar run            # 启动 + 实时数据流（Ctrl+C 退出）
hangar logs           # 实时数据流（仅查看，不启动）

hangar check          # 快速检查：运行中/已停止 + Web 地址
```

### 3.3 配置管理

```bash
hangar config         # 编辑配置文件 /etc/hangar/config.yaml
```

### 3.5 数据流解读

| 前缀 | 含义 | 刷新频率 |
|------|------|----------|
| `SYS:` | 系统负载/内存/运行时间 | 1Hz |
| `DATA:` | 四模块连接状态：MAVLink/MQTT/STM32/Camera | 1Hz |
| `TELEM:` | 无人机遥测：飞行模式/高度/速度/电量/卫星 | 1Hz |
| `MAVLink HB:` | 飞控心跳原始数据 | 按飞控发送频率 |

**连接状态标识**：
- `UP` / `DOWN` — 模块连接状态
- `HB:0s` — 距上次心跳秒数（`--` 表示从未收到）
- `MSG:--` — 距上次消息秒数
- `RPT:--` — 距上次上报秒数
- `SNAP:--` — 距上次截图秒数

## 四、Web 管理看板

### 4.1 访问

浏览器打开：`http://<机库IP>:8080`

**认证**：如果开启了登录认证，会显示登录页面。登录后关闭浏览器 30 分钟内重开无需重登。
认证开关在 **系统配置 → 认证设置** 中控制。

五个标签页：

| 标签 | 功能 |
|------|------|
| 总览 | 实时连接状态卡片 + 无人机仪表盘 + 机库状态 |
| 配置 | 系统参数配置（MQTT/MAVLink/摄像头/STM32/决策） |
| 控制 | 手动指令（开门/关门/锁止/解锁/截图/重启服务/重启终端） |
| 日志 | 系统事件日志 + 告警历史 |
| 角色规则 | 决策引擎规则查看/启用/禁用 |

### 4.2 配置保存

保存方式：

| 方式 | 说明 |
|------|------|
| 全局 **[保存配置]** | 保存所有板块 |
| 单板块 **[保存]** | 每个配置板块各自的保存按钮 |

保存后写入 `/etc/hangar/local.yaml`（**永久保留，代码更新不丢失**），服务自动重启。

配置面板：

| 板块 | 内容 |
|------|------|
| MQTT 地面站 | Broker、端口、用户名密码、Topic 前缀 |
| MAVLink 无人机 | 连接方式(TCP/串口)、遥测刷新率 1-10Hz |
| 摄像头 RTSP | IP、端口、RTSP URL |
| STM32 串口 | 设备路径、波特率 |
| VPN / Tailscale | Auth Key（交付客户时配置） |
| 认证设置 | 启用登录、用户名密码、会话超时 |
| 决策引擎 | RTL 自动开门、低电量阈值、失联超时 |

### 4.3 实时数据流

总览页面数据每 250ms 自动刷新（4Hz），与飞控遥测刷新率匹配。

系统资源栏底部显示 **Broker 状态**（✅ 运行 / ❌ 停止）。

后台提供 SSE 实时推送端点 `/api/stream`（100ms 间隔），供高级用户自行对接。

### 4.4 MAVLink 连接方式

在「系统配置 → MAVLink 无人机」中切换：

| 连接方式 | 使用场景 | 需填参数 |
|----------|----------|----------|
| TCP (4G图传) | 远程飞控通过 4G 模块连接 | 4G模块IP + 端口(默认5760) |
| 串口 (USB直连) | USB 线直接插飞控 | 串口设备路径 + 波特率(默认115200) |

### 4.5 STM32 串口选择

独立串口下拉框，避免与 MAVLink 抢口：

```
/dev/ttyUSB0  ← 默认（与 MAVLink 分用）
/dev/ttyUSB1
/dev/ttyACM0  ← MAVLink 在用，不要选这个
/dev/ttyACM1
自定义路径...  ← 手动输入
```

## 四-A、客户交付配置流程

> 交付客户前，需完成以下配置，使设备加入客户自己的 Tailscale 网络。

### 4A.1 客户准备

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 浏览器打开 https://login.tailscale.com | 用客户自己的 GitHub/Google 账号注册 |
| 2 | 进入 Settings → Keys | 左侧菜单底部 |
| 3 | 点击 "Generate auth key..." | 选 Reusable 类型，点 Generate |
| 4 | **复制生成的 key**（tskey-auth-xxxx） | 只显示一次，务必复制保存 |

### 4A.2 机库 WebUI 配置

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 浏览器打开 `http://机库IP:8080` | 默认无需登录 |
| 2 | 切换到 **系统配置** 标签 | 顶部导航 |
| 3 | 找到 **VPN / Tailscale** 板块 | 粘贴 Auth Key → 点 **[保存]** |
| 4 | 找到 **认证设置** 板块 | 启用登录 → 改用户名密码 → 点 **[保存]** |
| 5 | 等待约 10 秒服务自动重启 | 刷新页面 |

### 4A.3 验证

```bash
# SSH 进 RK3568 确认
tailscale status
# 应看到设备在线，获得客户网络的虚拟 IP（100.x.x.x）
```

### 4A.4 远程调度系统连接

装机器的 PC 也装 Tailscale 并加入**同一个客户账号**，MQTT 连接：

| 参数 | 值 |
|------|------|
| Broker | `100.x.x.x`（RK3568 的 Tailscale IP） |
| 端口 | `1883` |
| 用户名 | `hangar` |
| 密码 | 部署时设定的密码 |

> 配置永久保留在 `/etc/hangar/local.yaml`，后续更新代码不会丢失。

## 五、配置文件详解

配置文件位置：

| 文件 | 用途 | 是否可覆盖 |
|------|------|-----------|
| `/opt/hangar/config.yaml` | 默认模板（代码更新时覆盖） | ✅ |
| `/etc/hangar/local.yaml` | **用户配置（永久保留）** | ❌ 永不覆盖 |

> WebUI 上修改的任何配置都会存入 `local.yaml`。
> 代码更新只覆盖默认模板，你的配置不受影响。

### 5.1 日志

```yaml
log:
  level: INFO           # DEBUG | INFO | WARNING | ERROR
  format: "text"        # text(人读) | json(机器读)
  dir: ./data/logs
  max_days: 30          # 日志保留天数
```

### 5.2 MQTT 地面站

```yaml
mqtt:
  enabled: false                # 是否启用 MQTT
  broker: "mqtt.example.com"    # Broker 地址
  port: 1883                    # 端口
  username: "admin"             # 用户名
  password: "your_password"     # 密码
  keepalive: 30                 # 心跳间隔(秒)
  status_interval: 5            # 状态上报间隔(秒)
  topic_prefix: "hangar/"       # 主题前缀
  qos: 1                        # QoS 等级(0|1|2)
  reconnect_min: 2              # 重连最小间隔(秒)
  reconnect_max: 60             # 重连最大间隔(秒)
```

### 5.3 MAVLink 无人机

```yaml
mavlink:
  connection: "tcp"             # 连接方式：tcp(4G图传) | serial(USB直连)
  host: "192.168.x.x"           # TCP 模式：4G模块IP
  port: 5760                    # TCP 模式：端口
  device: "/dev/ttyACM0"        # 串口模式：设备路径
  baudrate: 115200              # 串口模式：波特率
  heartbeat_timeout: 5          # 心跳超时(秒)，超时触发失联告警
  system_id: 255                # MAVLink 系统ID
  reconnect_interval: 3         # 重连间隔(秒)
```

### 5.4 STM32 串口

```yaml
stm32:
  port: "/dev/ttyUSB0"          # 串口设备路径
  baudrate: 115200              # 波特率
  data_bits: 8                  # 数据位
  parity: "N"                   # 校验位：N(无)|E(偶)|O(奇)
  stop_bits: 1                  # 停止位
  cmd_timeout: 0.5              # 指令超时(秒)
  cmd_retry: 3                  # 重试次数
  status_interval: 1            # 主动上报间隔(秒)
```

### 5.5 VPN / Tailscale

| 字段 | 默认值 | 说明 |

### 5.7 摄像头 RTSP

```yaml

  enabled: true
  ip: "10.6.3.57"               # 摄像头 IP
  port: 554                     # RTSP 端口
  username: "admin"             # 用户名
  password: ""                  # 密码
  channel: 1                    # 通道号
  stream: 0                     # 0=主流 1=子流
  rtsp_url: ""                  # 直接填 RTSP URL（留空则用上面字段拼接）
```

### 5.8 决策引擎

```yaml
decision:
  auto_open_on_rtl: true        # RTL 返航自动开门
  low_battery_threshold: 20     # 低电量阈值(%)
  lost_timeout: 30              # 失联超时(秒)
  rtl_alt_threshold: 100        # RTL 高度判断阈值(m)
  door_open_delay: 5            # 开门延迟(秒)
```

**规则说明**：

| 规则 | 触发条件 | 动作 |
|------|----------|------|
| 返航自动开舱 | 飞控进入 RTL 模式 | 自动开舱门 |
| 低电量告警 | 电池低于阈值 | MQTT 告警 |
| 失联告警 | 心跳超时 | MQTT 告警 |
| 机库告警 | 传感器异常 | MQTT 告警 |
| MQTT 转发 | 收到地面站指令 | 转发给 STM32 |

## 七、常见问题

### Q1: MAVLink 显示 DOWN 无心跳

1. 检查连接方式：TCP 模式确认 4G 模块 IP 可达 `ping <IP>`
2. 串口模式确认设备存在 `ls /dev/ttyACM* /dev/ttyUSB*`
3. 检查 MAVLink 和 STM32 是否用了同一串口（不能共用）
4. 尝试 `hangar restart`

### Q2: STM32 反复 DISCONNECTED

1. 确认 STM32 板已上电，USB 线已插
2. 确认配置的串口设备存在 `ls -la <设备路径>`
3. 确认串口没有被 MAVLink 占用

### Q3: 网页显示问号

1. 确认 `dashboard.html` 是最新版
2. 清除浏览器缓存后刷新

### Q4: 配置保存后不生效

WebUI 保存时会自动重启服务（约 3-5 秒）。若仍不生效：
1. 确认保存时有绿色"已保存"提示
2. 手动执行 `sudo systemctl restart hangar`

### Q5: 代码更新后配置丢失

不会丢失。WebUI 修改的配置保存在 `/etc/hangar/local.yaml`，代码更新只覆盖默认模板。
`local.yaml` 永不覆盖，始终保留你的配置。

### Q6: 登录认证怎么开关

**开启**：WebUI → 系统配置 → 认证设置 → 勾选"启用登录认证" → 保存。

**密码输入框右侧有"显/隐"按钮，可查看实际输入的密码。**

> ⚠️ **应急手段**：如果忘记密码或登录失败无法进入 WebUI，SSH 执行以下命令强制关闭认证：
> ```bash
> sudo tee /etc/hangar/local.yaml << 'EOF'
> auth:
>   enabled: false
> EOF
> sudo rm -rf /opt/hangar/modules/__pycache__
> sudo systemctl restart hangar
> ```
> 关闭后可无密码进入 WebUI，重新设置密码后再开启。

默认用户名 `admin`，默认密码 `admin123`，建议首次登录后修改。

### Q7: 横滚/俯仰角度不对

已修复。飞控返回的是弧度值，系统自动转为角度（`math.degrees()`）。
横滚 ±180°，俯仰 ±90°，偏航角 -180°~+180° 为正确范围。

### Q8: CPU 显示跳动

已修复。CPU 每 2 秒采样一次（与 htop 一致），显示的是 EMA 平滑值，不会因刷新频率抖动。

### Q9: 数据延迟约 1 秒

已修复。总览页面每 250ms 轮询一次 /api/health（4Hz），与飞控遥测刷新率匹配。

### Q10: 如何查看实时飞控数据

```bash
hangar logs
# 或
hangar run
```
关注 `TELEM:` 行：飞行模式/高度/地速/电量/卫星数

## 八、云台存储访问 (新增)

### 8.1 拓扑

```
客户 PC (任意地方)                    RK3568 机库                     飞机 4G 模块
   │                                      │                              │
   │ Tailscale 网络 ──────────────────▶  │                              │
   │                                      │ WiFi H4T_4G ────────────────▶ │
   │                                      │   192.168.144.x               │
   │                                      │                              │
   │◀─────── HTTPS / RTSP / UDP ───────│◀─────── 云台 API ──────────│
```

云台 (思翼 SIYI) 通过 4G 模块的 WiFi (`H4T_4G`) 暴露内网接口 `192.168.144.25:82` (HTTP) 和 `:8554` (RTSP)。RK3568 作为桥梁:
- **局域网客户**: 直连 RK3568, 通过 eth0 拿到子网路由
- **公网客户**: 通过 Tailscale 子网路由, 自动学到 `192.168.144.0/24`

### 8.2 客户访问方式

| 客户位置 | 推荐方式 | URL/操作 |
|---|---|---|
| 机库现场 (同网段) | 浏览器 + SIYI GCS | `http://192.168.2.78:8080/camera` 或 `192.168.144.25:8554` |
| 公网 (Tailscale) | 浏览器 (主) | `http://100.84.131.95:8080/camera` |
| 公网 (Tailscale) | SIYI GCS (备) | 连 `192.168.144.25:37260` (UDP) |

浏览器打开 `http://<机库IP>:8080/camera`:

**功能**:

- ✅ 自动 URL 重写 (思翼返回的占位 host → 实际 IP)
- ✅ 缩略图预览 (Web 端)

### 8.4 云台存储 API 速查

```
基础 URL: http://192.168.144.25:82/cgi-bin/media.cgi

GET /api/v1/getdirectories?media_type=0   # 列子目录 (0=照片 1=视频)
GET /api/v1/getmediacount?media_type=0&path=xxx
GET /api/v1/getmedialist?media_type=0&path=xxx&start=0&count=10
```

返回的 JSON 里有 `list[].url`, 但 host 是占位 `xxx`, 实际访问时会被代理脚本改写成 `192.168.144.25:82`。

### 8.5 网络配置 (`config.yaml`)


### 9.5 性能预期

## 十、网络架构与持久化 (新增)

### 10.1 双网卡架构

```
┌──────────────────────────────────────────────┐
│ RK3568                                        │
├──────────────────────────────────────────────┤
│ eth0 (192.168.2.78/24)  ← 主网/公网           │
│   └─ gateway 192.168.2.1                     │
│   └─ 用 netplan 静态配                        │
│                                               │
│ eth1 (10.6.3.1/24)     ← 海康摄像头           │
│   └─ never-default                           │
│   └─ dnsmasq DHCP 给摄像头自动分 IP           │
│                                               │
│ wlan0 (192.168.144.100) ← 4G模块 WiFi (云台) │
│   └─ 自动连 H4T_4G                           │
│   └─ never-default                           │
│   └─ autoconnect-priority 100                │
│   └─ 飞机回来时自动重连 (wifi-watchdog)       │
│                                               │
│ tailscale0 (100.84.131.95) ← 跨公网           │
│   └─ 广播 192.168.144.0/24 给客户            │
└──────────────────────────────────────────────┘
```

### 10.2 开机自启项

| 服务 | 作用 | 启动时机 |
|---|---|---|
| `systemd-networkd` | netplan 静态 IP | 开机 |
| `NetworkManager` | WiFi + autoconnect | 开机 |
| `wifi-autoconnect.service` | 开机 30s 后首次连 H4T_4G | 开机 |
| `wifi-watchdog.service` | 持续保活 (60s 检测) | 一直跑 |
| `iptables-persistent` | 恢复 FORWARD 规则 | 开机 |
| `go2rtc.service` | RTSP 代理 | 开机 |
| `hangar.service` | 主程序 | 开机 |
| `tailscaled.service` | Tailscale 守护 | 开机 |

### 10.3 重启验证 (8 步)

```bash
echo "=== 1. eth0 ==="; ip addr show eth0 | grep "inet "
echo "=== 2. WiFi ==="; nmcli device status | grep wlan0
echo "=== 3. soft-block ==="; rfkill list | grep -A 1 phy0
echo "=== 4. ip_forward ==="; cat /proc/sys/net/ipv4/ip_forward
echo "=== 5. iptables ==="; sudo iptables -L FORWARD -n | grep -E "192.168.144|policy"
echo "=== 6. Tailscale ==="; sudo tailscale status | head -3
echo "=== 7. 云台通 ==="; ping -c 2 192.168.144.25
echo "=== 8. 公网通 ==="; ping -c 2 baidu.com
```

**8 项全绿 = 网络地基正常**。

### 10.4 飞机离开/返回 WiFi 重连

- 飞机离库 → 4G 模块 WiFi 信号消失 → wlan0 自动断开
- 飞机返航进入机库范围 → 4G 模块 WiFi 信号再次出现
- **60 秒内**:
  - NetworkManager 扫描到 H4T_4G (优先级 100) → 自动重连
  - 或 wifi-watchdog 检测到断开 → 强制触发重连

### 10.5 一键重置网络 (万不得已)

```bash
sudo bash /home/kickpi/rk3568_app/deploy/setup_network.sh
sudo systemctl restart NetworkManager
sudo systemctl restart wifi-watchdog
```
